# feature/editor

## Files

- `EditorViewModel.kt` — one VM for all tabs; per-path `EditorSession` cache; parse and save debounce.
- `EditorUiState.kt` — `EditorUiState`, `EditorEvent`, `EditorAction`, `DirtyChange`.
- `ui/EditorPane.kt` — the editor screen; routes by `FileKind` and owns find/replace.
- `ui/MarkdownFields.kt` — `RenderedMarkdownField` / `LiveMarkdownField` / `RawMarkdownField`, plus the checkbox and link hit-test.
- `ui/MarkdownVisualTransformation.kt`, `ui/MarkdownStyles.kt` — mask projection into the field; style lookup.
- `ui/FormatPopup.kt`, `ui/PopupTextToolbar.kt` — hover format toolbar; mobile selection toolbar.
- `ui/DocumentOutline.kt` — top-right overview button (hover on desktop, tap to pin on mobile) listing `outlineOf(document)` (`core/markdown/Outline.kt`); shown for Markdown with 2+ headings.
- `ui/EditorHeader.kt`, `ui/EditorStatusBar.kt`, `ui/EditorOverflowMenu.kt`, `ui/FindReplaceBar.kt`.

## Seam

- `state: StateFlow<EditorUiState>`, `onEvent(event: EditorEvent)`, `dirtyChanges: SharedFlow<DirtyChange>`, `actions: SharedFlow<EditorAction>`, `suspend flushAll()`, `closeSpace()`.
- One VM owns every tab: `sessions: Map<FilePath, EditorSession>` plus `activePath`. Switching tabs re-publishes the cached session, so text, caret, mode and dirty state survive with no re-read and no re-parse. Do not introduce a VM per tab.
- Tabs are not this feature's business: `app/ui/WorkspaceHost.kt` collects `dirtyChanges` and `actions` to drive `TabsViewModel`, and pushes `EditorEvent.Open` for the active tab.
- Parsing is debounced 80 ms, so the document usually lags the field by a keystroke. `MarkdownVisualTransformation` projects the stale document forward through `textRevisionBetween` — do not replace that with an identity fallback.
- `applyFormat` parses synchronously before publishing, the one deliberate bypass of the debounce: it is the only way `value.text` and `document.text` agree in the same frame. Read the root `AGENTS.md` "Markdown pipeline" section before changing formatting, marker masking or task toggling.
- **Soft-keyboard list editing is owned by the input connection, never by the VM.** On Android, `ListAwareImeInput` (`core/platform`) wraps the field's `InputConnection` through `InterceptPlatformTextInput`. Every list rewrite is applied *through that connection*, so it goes through Compose's own `EditProcessor` inside the keyboard's own call. The processor and the keyboard can never disagree about the text, and no keyboard follow-up can land on a stale buffer and revert it. Two triggers, both pure functions in `core/markdown/ImeEdits.kt`:
  - Key events from the keyboard (`sendKeyEvent`: SwiftKey sends Return mid-word as `KEYCODE_ENTER`, and some keyboards send `KEYCODE_DEL`) go to `imeKeyEdit`. Enter on a list line becomes `ContinueList`, and Backspace right after a checkbox becomes `DeleteTaskMarker`. The key down is consumed and its key up swallowed; anything else passes through untouched.
  - Text commands (`commitText("\n")` from Gboard, `deleteSurroundingText` …) pass through, and when the keyboard's outermost batch closes, `imeBatchFixup(before, after, selection)` compares the text before and after the batch. A single inserted newline is continued (`continueListAfterNewline`), and a deletion inside a raw checkbox is completed (`taskMarkerBackspaceEdit`).
  - The connection needs the processor's current text, which `RecordingInputConnection` only learns on recomposition. So each field keeps an `ImeBufferMirror`, updated from every raw `onValueChange` (processor output, before `snapTaskCaret`) and from `SideEffect` on every composition (`processor.reset` runs in the same composition).
  - A fixup reaches the VM as `EditorEvent.TextChanged(value, parseNow = true)` (the field routes it to `onImeFixup` while `mirror.applyingFixup`). It parses synchronously, like `applyFormat`, so an inserted `- [ ] ` never renders raw.
  - Desktop has no soft keyboard: the `jvm` actual is a pass-through, and a hardware Return/Backspace is caught by `Modifier.enterContinuesList` / `backspaceRemovesTaskMarker` and handled as a `FormatAction` (`applyFormat`).
  - Do not reintroduce VM-side detection of typed newlines or deletions, deferred `launch(dispatchers.main)` fixes, or stale-buffer rebasing. Every one of those raced the keyboard, which is the bug this design removes.
  - The wrapper must override **every** editing entry point, including the `TextAttribute` overloads added in API 33/34 (`commitText`, `setComposingText`, `setComposingRegion`, `replaceText`). Compose's `RecordingInputConnection` does not implement them, so `InputConnectionWrapper` forwards them straight to the target's interface defaults, bypassing the 2-argument overrides. Modern keyboards call those overloads, and missing them made every soft-keyboard Enter go unseen.
  - Keyboards send a key event *inside* their own batch (SwiftKey: `beginBatchEdit`, `finishComposingText`, `sendKeyEvent(ENTER)`, `endBatchEdit`). An edit the wrapper makes there is only queued, and it flushes at the keyboard's `endBatchEdit`. So two rules hold for it: the batch's after-the-fact check is skipped (`textBeforeBatch = null`), or `imeBatchFixup` would treat our own inserted newline as a typed one and "end the list" by deleting the marker it just inserted; and `mirror.applyingFixup` stays up until the outermost batch closes, or the flush reaches the VM as ordinary typing, goes through the 80 ms debounced parse, and the raw `- [ ] ` flashes.
  - Diagnose on a device with `adb shell setprop log.tag.VerseIme DEBUG` then `adb logcat -s VerseIme`. Every connection call, batch close (with before/after text and whether a fixup applied) and key event is logged; nothing is logged unless the tag is enabled.
- `publishEdit` maps the field's IME composition through the edit (`compositionThroughEdit`) instead of publishing a null-composition value: passing a null composition commits the keyboard's in-flight composition behind its back.
- Backspace right after a task checkbox (caret anywhere from `]` to the content start, `caretAfterTaskMarker`) removes the whole `- [ ] ` prefix in one press, keeping the line's indent and landing the caret on the content.
- Undo/redo is our own `EditHistory`, one per `EditorSession` (carried across renames). `textChanged` records every text change; typing within 1 s coalesces into one step, and a line break, a format action, a checkbox toggle or a title jump (`boundary = true`) starts a new one. Connection fixups (`parseNow`) are deliberately *not* boundaries, so one undo removes Enter and its inserted marker together. `restore` parses synchronously like `applyFormat`, so an undone marker never renders raw. Only the mobile header (`CompactHeaderActions`) shows the buttons; desktop Ctrl+Z is still the text field's own.
- `continueLists` is only passed true for `FileKind.Markdown`: `RawMarkdownField` also renders plain `.txt`, and consuming Enter there would leave the file uneditable.
- `EditorEvent.JumpToHeading` (and `JumpToAnchor`) moves the caret and sets `EditorUiState.revealRequest` (offset + monotonic id). The fields consume it in their caret-scroll effect by calling `bringIntoView` with a rect as tall as the viewport, which top-aligns the heading; a plain caret move still scrolls minimally.

## Gotchas

- The field is the legacy `BasicTextField(TextFieldValue, visualTransformation = …)`. The newer `TextFieldState` API cannot hide marker characters, so a "modernisation" here is a regression.
- A collapsed caret never rests inside a checkbox's source range: the mask maps every transformed position of the drawn box back to the range start, so a click "just after the box" would otherwise land before `[`, and typing there breaks the GFM task (`- x[ ] …`), un-hiding the dash and brackets. `snapTaskCaret` in `MarkdownFields.kt` moves the caret to the near side on arrival — clicks decide by their transformed offset relative to the glyph (`caretTargetForTaskRange`), keyboard moves by the previous caret. The far side is past the single space after `]` (`taskCaretRange`), not `]` itself: typing between `]` and that space gives `- [ ]x`, which is not a GFM task and un-hides the dash. The snap is skipped on a revealed line, where the raw brackets are legitimately editable.
- The note title bar is part of the scrolling content, not a pinned header: it renders at the top of `EditorContent`'s scrolling column for Markdown/Text, and only image/other viewers keep it above the content. Enter in the title emits `EditorEvent.StartNoteBody`, which puts a blank line above the existing text and the caret at offset 0. Backspace at document offset 0 emits `EditorEvent.JumpToTitle`, which drops a leading empty line and moves focus to the title with the caret after the name (through `focusTitleRequestId`, the one-shot counter the title field consumes).
- `focusContentRequestId` is a monotonic counter consumed once by the field; do not collapse it to a boolean.
- The header rename, overflow menu and lock/favourite buttons live in `EditorHeader.kt`; their VM events are still `EditorEvent.*`.

Covered by `shared/src/commonTest/.../EditorFormattingTest.kt` (it pins the synchronous parse).
